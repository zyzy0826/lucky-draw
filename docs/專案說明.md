# 社博攤位抽獎轉盤 — 專案規格書

## 專案概述

做一個**網頁版抽獎轉盤**，用於社團博覽會（社博）擺攤現場，讓來訪的人轉動轉盤抽獎。獎品數量會隨著被抽中而遞減，抽完即止。

整個應用打包成**單一 HTML 檔案**（CSS 和 JS 全部 inline），現場用瀏覽器直接開啟檔案即可運作，不需要網路連線、不需要啟動 local server。所有狀態存在瀏覽器的 `localStorage` 裡。

技術棧請使用 **vanilla HTML/CSS/JS**，不要使用框架（React/Vue 等），確保產出就是一個可以直接雙擊打開的 `.html` 檔。

---

## 獎品設定

| 獎品名稱 | 初始數量 | 建議機率（可微調） |
| -------- | ------- | ---------------- |
| 便利貼    | 60      | 約 85%           |
| 咖啡杯    | 5       | 約 10%           |
| 托特包    | 5       | 約 5%            |

規則說明：

- **沒有「銘謝惠顧」**，轉盤上只有以上三種獎品的格子。
- 每次抽中一個獎品，該獎品的**剩餘數量 −1**。
- 某獎品數量歸零後，轉盤**格子外觀不變**（不會消失或縮小），但該獎品**不可能再被抽中**，機率自動分配給其他仍有庫存的獎品。
- 當所有獎品都抽完（便利貼 + 咖啡杯 + 托特包全部歸零），轉盤進入「已結束」狀態，顯示「獎品已全部抽完！」的提示，無法再轉動。

### 機率分配邏輯

基礎機率如上表。當某獎品庫存歸零時，將它原本的機率**按比例分配**給剩餘有庫存的獎品。

範例：托特包抽完後，原本 5% 的機率按比例分給便利貼和咖啡杯，便利貼變為 ≈89.5%，咖啡杯變為 ≈10.5%。

## 頁面與功能

### 1. 抽獎頁面（一般訪客看到的）

這是主畫面，攤位上的人會直接操作這個頁面。

**轉盤區域**：

- 視覺上是一個圓形轉盤，分成多個扇形格子，每個格子標示獎品名稱。
- 格子的分布建議：便利貼占大多數格子，咖啡杯和托特包各占少數格子，格子數量大致反映機率比例。
- 轉盤需要有旋轉動畫，旋轉時間約 3～5 秒，帶有 ease-out 減速效果。
- 旋轉結束後，指針指向的格子就是抽中的獎品。

**操作流程**：

1. 頁面上有一個明顯的「開始抽獎」按鈕（或點擊轉盤本身觸發）。
2. 轉盤旋轉 → 減速 → 停下。
3. 彈出結果：顯示「恭喜你抽中了 ○○○！」，搭配該獎品的視覺強調（例如放大文字、灑花動畫等慶祝效果）。
4. 結果彈窗上有一個「確認 / 下一位」按鈕，**只有按了這個按鈕才能進行下一次抽獎**。這是為了讓攤位志工確認獎品已發出後才放行下一位。
5. 在轉盤旋轉期間和結果顯示期間，「開始抽獎」按鈕要被禁用，防止連續觸發。

**畫面資訊**：

- 轉盤下方或側邊顯示目前各獎品的**剩餘數量**，讓排隊的人知道還有什麼可以抽。
- 如果所有獎品都抽完了，轉盤區域顯示「獎品已全部抽完，感謝參與！」。

**響應式設計**：

- 需要同時支援平板（觸控操作）和筆電（滑鼠操作）。
- 轉盤在不同螢幕尺寸下要自適應，保持圓形且不被裁切。
- 按鈕大小要適合手指點擊（至少 44px × 44px）。

### 2. 管理後台

後台用來讓攤位負責人管理獎品庫存和查看紀錄。

**進入方式**：

- 在主畫面的角落放一個不顯眼的入口（例如小齒輪 icon 或隱藏的可點擊區域），點擊後要求輸入密碼。
- 密碼寫死在程式碼裡即可（例如預設密碼 `admin123`，可以在原始碼裡改）。
- 後台和抽獎頁面在同一個 HTML 檔案內切換，不需要路由。

**後台功能**：

- **即時庫存總覽**：顯示每個獎品的初始數量、已抽出數量、剩餘數量。
- **手動調整庫存**：可以增加或減少任一獎品的剩餘數量（應對臨時補貨或修正錯誤的情境）。
- **抽獎紀錄**：列出每一筆抽獎的時間戳和抽中的獎品名稱，最新的排在最上面。
- **重置功能**：一鍵將所有獎品數量恢復為初始值、清空抽獎紀錄。需要二次確認（例如「確定要重置嗎？」的對話框）。
- **匯出紀錄**（nice to have）：可以將抽獎紀錄匯出為 CSV 檔案。

## 技術需求

### 資料持久化

- 使用瀏覽器的 `localStorage` 儲存所有狀態（獎品庫存、抽獎紀錄）。
- 頁面重新整理後，狀態不會遺失。
- 管理後台修改庫存時，抽獎頁面要能即時反映（可以在每次操作前重新讀取 localStorage，或用 `storage` 事件監聽同源跨分頁的變更）。

### 部署方式

- 最終產出是**單一 `.html` 檔案**，用瀏覽器直接開啟即可（`file://` 協定），不需要 HTTP server。
- 不需要任何 build 步驟、不需要 npm install、不需要網路連線。
- 請在檔案開頭附上簡短的 HTML 註解，說明：用途、如何修改獎品設定、預設管理密碼。

### 程式碼品質

- 程式碼有基本的註解，關鍵邏輯（機率計算、庫存扣減）要有清楚的說明。
- 獎品設定（名稱、數量、機率、顏色）集中在 JS 最上方的一個 config 物件裡，方便未來修改，並加上註解標示。

## 視覺設計方向

- 風格：活潑、有活力，適合社團博覽會的熱鬧氛圍。
- 轉盤配色：每個獎品用不同顏色的扇形區塊，顏色對比要夠大，遠處也能看清。
- 開獎動畫：可以加一些慶祝效果（confetti、彈跳文字等），但不要過於花俏影響效能。
- 整體 UI 要乾淨，主畫面的視覺重心放在轉盤上，不要有多餘的裝飾元素干擾操作。

## 不需要的功能（明確排除）

以下功能**不需要做**，避免過度設計：

- 不需要使用者登入或輸入任何個人資訊（email、姓名等）。
- 不需要防重複抽獎的機制（由現場志工口頭控管）。
- 不需要後端伺服器、資料庫、或任何網路連線。
- 不需要任何外部 CDN 資源（所有 CSS/JS 必須 inline）。
- 不需要音效。
- 不需要多語系。
